# 핀 남기기·고치기 스펙

## 1. 개요

| 항목 | 값 |
| --- | --- |
| 문서명 | spec_pin |
| 작성일 / 최종 수정일 | 2026-11-14 / 2026-11-14 |
| 버전 | 1.0 |
| 기준 커밋 ID | 1a40209 |

- **기능명:** 핀 생성(UC1), 핀 상세·편집·삭제(UC2), 핀 데이터·카테고리·DB 기본값, 슬래시 명령
- **목적 (Why):** 위치에 고정된 개인 메모를 만들고 고치는 것이 다른 모든 기능(지도 표시·목록·길안내)이 다루는 데이터의 원천이다.

## 2. 목표 및 범위

### In Scope

- 현재 위치 또는 지도에서 고른 위치에 제목·메모·카테고리를 가진 핀 생성
- 핀 상세 패널에서 제목·메모·카테고리 수정, 삭제
- 내장 카테고리 6개와 저장된 사용자 카테고리의 조회
- `LorePinDB` 기본값 채우기와 초기화
- 슬래시 명령 `/lp`·`/lorepin`

### Out of Scope

- 만든 뒤 핀 위치(지도·좌표) 변경 → 상세 패널은 위치를 보여 주기만 한다
- 사용자 카테고리를 만들고 지우는 화면

## 3. 요구사항

### 3.1 사용자 스토리

- `US#1` [as-built] 탐험하는 플레이어로서, 발견한 장소를 다시 찾기 위해, 지금 위치나 지도에서 고른 위치에 메모를 남기고 싶다 → FR#1~FR#5
- `US#7` [요구사항] 팝업·패널에서 입력하는 플레이어로서, 저장이 왜 안 되는지 바로 알기 위해, 잘못된 입력은 저장 전에 그 자리에서 보이고 실패 안내는 보고 있는 화면에 보이길 원한다 → FR#28~FR#30
- `US#2` [as-built] 핀을 쌓아 가는 플레이어로서, 기록을 정확하게 유지하기 위해, 남긴 핀의 내용을 고치거나 지우고 싶다 → FR#6~FR#9

### 3.2 기능 요구사항

- `FR#1` [요구사항] 제목이 없거나 공백뿐이면 핀을 만들지 않는다. 공백 판정은 생성·편집이 같은 함수를 쓴다.

  ```
  Given 제목이 nil, 빈 문자열, 또는 공백(스페이스·탭·줄바꿈)뿐이다
  When  핀 생성을 요청한다
  Then  핀이 추가되지 않고 오류를 돌려준다. 생성 팝업·상세 패널은 이 상태에서 [저장] 을 막는다 (FR#28)
  ```

- `FR#2` [as-built] 저장된 핀 수가 최대 개수 설정(`maxPins`, 기본 500)에 이르면 만들지 않는다.

  ```
  Given 핀 수가 maxPins 이상이다
  When  핀 생성을 요청한다
  Then  핀이 추가되지 않고 최대 개수에 도달했다는 메시지(한도 포함)를 돌려준다
  ```

- `FR#3` [as-built] 만든 핀은 새 ID 를 받고 생성 정보가 기록된다.

  ```
  Given 제목이 있고 한도 미만이다
  When  핀 생성을 요청한다
  Then  id 는 nextPinId, nextPinId 는 1 증가
   And  메모가 없으면 "", 카테고리가 없으면 general
   And  createdAt = updatedAt = 현재 시각, createdBy = "캐릭터-서버"
   And  지도 표시·목록이 갱신된다
  ```

- `FR#4` [as-built] 현재 위치에 만들 때 위치를 얻지 못하면 만들지 않는다.

  ```
  Given 플레이어의 지도를 얻을 수 없다
  When  현재 위치 핀 생성 / 생성 팝업 열기 / [현재 위치] 를 요청한다
  Then  "사용 가능한 맵 없음" 실패 안내 (FR#30), 핀·팝업 변화 없음

  Given 지도는 있으나 위치가 없거나 (0, 0) 이다 (인스턴스 등)
  When  같은 요청
  Then  "현재 위치 확인 불가" 실패 안내 (FR#30), 핀·팝업 변화 없음
  ```

- `FR#5` [as-built] 생성 팝업은 좌표를 0~100 으로 입력받고, 지도에서 위치를 고를 수 있다.

  ```
  Given 생성 팝업이 열려 있다
  When  X 또는 Y 가 숫자가 아니거나 0~100 밖이다
  Then  그 칸이 강조되고 [저장] 이 막힌다 (FR#28, FR#29), 핀을 만들지 않는다

  When  [지도에서 선택] → 지도 캔버스를 좌클릭한다
  Then  그 지도·좌표로 팝업이 다시 열리고, 입력하던 제목·메모·카테고리가 유지된다

  When  지도 선택 중 우클릭·ESC 를 누르거나 지도를 닫는다
  Then  선택이 취소되고 팝업이 선택 전 위치·입력값으로 다시 열린다. ESC 는 지도를 닫지 않는다
  ```

- `FR#6` [as-built] 상세 패널은 제목·메모·카테고리를 바로 편집할 수 있고, 저장하지 않은 변경을 표시한다.

  ```
  Given 상세 패널이 열려 있다
  When  제목·메모·카테고리 중 하나가 원래 값과 달라진다
  Then  제목 옆에 * 표시, 버튼이 [저장][취소][닫기] 로 바뀐다
  When  값을 원래대로 되돌린다
  Then  * 가 사라지고 [웨이포인트][TomTom][삭제][닫기] 로 돌아간다
  ```

- `FR#7` [as-built] 상세 패널의 저장은 바뀐 필드를 반영하고, 취소는 원래 값으로 되돌린다.

  ```
  When  [저장] (제목이 비었거나 공백뿐이면 [저장] 이 막혀 있다, FR#28)
  Then  제목·메모·카테고리가 반영되고 updatedAt 갱신, 지도·목록 갱신
  When  [취소]
  Then  필드가 패널을 연 시점(또는 마지막 저장) 값으로 돌아간다
  When  저장하지 않은 변경이 있는 채로 닫는다
  Then  버릴지 확인 대화상자, 확인해야 닫힌다
  ```

- `FR#8` [as-built] 핀 수정은 넘긴 필드만 바꾼다. 없는 ID 면 실패한다. [요구사항] 넘긴 제목이 비었거나 공백뿐이면(FR#1 판정) 실패한다.

  ```
  Given 핀이 있다
  When  일부 필드만 넘겨 수정한다
  Then  넘긴 필드만 바뀌고 나머지는 그대로, updatedAt 갱신
  Given 없는 ID
  When  수정한다
  Then  false 와 "핀 없음" 메시지, 데이터 변화 없음
  Given 핀이 있다
  When  제목을 공백뿐인 값으로 넘겨 수정한다 (다른 필드와 함께여도)
  Then  false 와 "제목 입력" 메시지, 어떤 필드도 바뀌지 않음
  ```

- `FR#28` [요구사항] 생성 팝업과 상세 패널의 [저장] 은 입력이 유효할 때만 누를 수 있다.

  ```
  Given 생성 팝업: 제목이 비었거나 공백뿐(FR#1 판정)이거나, X·Y 중 하나가 숫자가 아니거나 0~100 밖이다
  Then  [저장] 이 비활성이다
  Given 상세 패널: 저장하지 않은 변경이 있고(FR#6) 제목이 비었거나 공백뿐이다
  Then  [저장] 이 보이되 비활성이다
  When  입력을 고쳐 유효해진다 (글자 입력·지도에서 선택·[현재 위치] 포함)
  Then  즉시 [저장] 이 활성이 된다
  When  비활성 [저장] 위에 마우스를 올린다
  Then  막힌 이유(제목 입력 필요 / 좌표 0~100)가 툴팁으로 보인다
  ```

  - 판정은 입력 문자열만 보는 하나의 함수가 한다 → 생성 팝업·상세 패널·테스트가 같은 결과를 본다.
  - 좌표 판정은 `tonumber` 로 숫자가 되고 0 이상 100 이하인지다.
- `FR#29` [요구사항] 생성 팝업에서 판정을 통과하지 못한 좌표 칸(X·Y 각각)은 글자가 빨간색이 된다. 유효해지면 원래 색으로 돌아간다. 제목 칸은 강조하지 않는다 → 팝업을 막 연 빈 상태가 오류처럼 보이지 않게.
- `FR#30` [요구사항] 저장·실행을 시도해야 알 수 있는 실패는 화면 상단 오류 문구(`UIErrorsFrame`, 빨간색)로 보이고, 같은 문구를 채팅창에도 남긴다.

  | 실패 | 발생 자리 |
  | --- | --- |
  | 최대 핀 수 도달, 그 밖의 생성 실패 | 생성 팝업 [저장] |
  | 사용 가능한 맵 없음, 현재 위치 확인 불가 | 생성 팝업 열기(`/lp`·`/lp <제목>`), [현재 위치] |
  | 지도 선택 기능 사용 불가 | [지도에서 선택] |
  | 핀 없음 | 상세 패널 삭제 확인 |
  | TomTom 웨이포인트 생성 실패 | 상세 패널·목록 [TomTom] |

  - 결과 알림(생성·수정·삭제·초기화 완료), 슬래시 명령의 응답(도움말·사용법·`/lp detail`·`/lp delete` 의 핀 없음)은 지금처럼 채팅창에만 출력한다.

- `FR#9` [as-built] 삭제는 핀과 그 핀의 지도 표시·TomTom 웨이포인트를 함께 지운다.

  ```
  When  상세 패널 [삭제] → 확인
  Then  핀이 사라지고 "삭제됨" 안내, 패널 닫힘
  When  `/lp delete <id>` (확인 없음)
  Then  같은 결과. 없는 ID 면 "핀 없음"
  ```

- `FR#10` [as-built] 카테고리는 내장 6개(general, quest, danger, gather, scenic, complete) 뒤에 저장된 사용자 카테고리를 이어 붙인 목록이다. 기본 카테고리는 general 이다.
- `FR#11` [as-built] 사용자 카테고리 추가는 이미 있는 ID(내장 포함)면 거부한다. 아이콘·색을 주지 않으면 물음표 아이콘·흰색이다.
- `FR#12` [as-built] 지도 ID 로 그 지도의 핀만 조회하고, 제목·메모에서 대소문자 구분 없이 글자 그대로(패턴 아님) 검색한다. 빈 검색어는 전체다.
- `FR#13` [as-built] 슬래시 명령 `/lp`·`/lorepin`

  | 입력 | 동작 |
  | --- | --- |
  | (없음) | 현재 위치로 생성 팝업 |
  | `help`·`?` | 명령 도움말 출력 |
  | `list`·`l` | 목록 패널 |
  | `settings`·`config`·`opt` | 설정 패널 |
  | `delete`·`del`·`rm <id>` | 확인 없이 삭제 (FR#9) |
  | `detail`·`show`·`view <id>` | 상세 패널 |
  | 그 밖의 글 | 그 글을 제목으로 채운 생성 팝업 (바로 만들지 않음) |

  - 명령어는 대소문자를 구분하지 않고, 앞뒤 공백을 무시한다. `<id>` 가 숫자가 아니면 사용법을 출력한다.

### 3.3 비기능 요구사항

- `NFR#5` [as-built] 로드 시 `LorePinDB` 가 없으면 만들고, 없는 키만 기본값으로 채운다(중첩 테이블 포함). 핀만 초기화하면 핀과 다음 ID(1)만, 설정만 초기화하면 설정만 기본값으로 돌린다.

## 5. 화면 및 UI/UX

- 생성 팝업: 지도 이름·X·Y(0~100, 소수 1자리)·[현재 위치]·[지도에서 선택], 제목(최대 120자), 카테고리 드롭다운, 메모(최대 500자), [저장][취소]
- 상세 패널: 카테고리 아이콘, 제목·카테고리·메모 편집, 위치(지도 이름·좌표)·생성 시각·작성자 표시
- 결과 알림·슬래시 명령 응답은 채팅창에 `[LorePin]` 머리말로 출력한다. 입력 오류는 [저장] 비활성·칸 강조·툴팁(FR#28·FR#29), 실행 실패는 화면 상단 오류 문구 + 채팅창(FR#30)

## 6. 동작 로직 및 정책

### 6.1 지도에서 위치 지정 [FR#5]

- 지도 캔버스 위에 투명 오버레이를 덮어 클릭을 가로챈다 → 지도의 기본 클릭(하위 지역 진입·축소)보다 먼저 받는다
- 커서 위치를 캔버스 크기로 나눠 0~1 좌표로 바꾼다. 캔버스 밖이면 선택을 끝내고 팝업을 다시 열지 않는다

### 6.n 설계 결정

| 결정 | 선택 | 기각한 대안 | 근거 |
| --- | --- | --- | --- |
| `D#1` | 좌표를 0~1 로 저장하고 화면에서만 0~100 | 0~100 저장 | `C_Map`·`UiMapPoint` 가 0~1 을 쓴다 → 변환 없이 넘긴다 |
| `D#2` | 핀 ID 를 `nextPinId` 로 단조 증가, 삭제해도 재사용 안 함 (핀 전체 초기화 때만 1) | 배열 위치·빈 번호 재사용 | 슬래시 명령·TomTom UID 표가 ID 로 핀을 가리킨다 → 재사용하면 다른 핀을 가리킨다 |
| `D#3` | 계정 공유 SavedVariables | 캐릭터별 저장 | 같은 세계를 여러 캐릭터로 다닌다 → 기록도 공유해야 쓸모 있다 |
| `D#7` | 입력 오류는 [저장] 비활성으로 미리 막고, 실행 실패만 `UIErrorsFrame` 에 띄운다 | 모든 안내를 채팅창 / 모든 오류를 `UIErrorsFrame` / 출력 위치 선택(LibSink) | 채팅창은 대화에 묻혀 놓친다. 미리 막으면 오류 문구 자체가 필요 없다. `UIErrorsFrame` 은 WoW 기본 오류와 같은 자리라 익숙하다. LibSink 는 외부 라이브러리 없음 원칙(`NFR#4`)과 맞지 않는다 |
| `D#8` | 비활성 [저장] 의 툴팁은 버튼이 비활성이어도 마우스 이벤트를 받게 해서 띄운다 | 툴팁 없음 | 비활성 버튼만 보고는 왜 막혔는지 알 수 없다. WoW 버튼은 비활성이면 기본으로 OnEnter 를 받지 않는다 |
